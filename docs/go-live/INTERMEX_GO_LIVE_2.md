## Authority and external decisions

Intermex is the customer brand. CornerMex owns canonical orders, inventory and lifecycle. Stripe owns payment truth. Zoho owns accounting documents. No accounting result changes canonical payment truth.

Linda/Intermex must confirm Zoho Books versus Invoice, organization and data center, AED/UAE VAT/TRN and tax mapping, invoice numbering/issuance policy, supported customer matching identity, partial/full refund and credit-note treatment, approved document hosts, and who resolves ambiguous creates/refund actions. These are EXTERNAL_BLOCKER items; the adapter does not invent a credit-note API or automatically write one.

Stripe inputs: approved account and explicit mode, secret and signing-secret custody, public application URL, webhook endpoint/event subscription, read-only recovery permissions, evidence of delivery and controlled test results. Webhook events: checkout.session.completed, async_payment_succeeded, async_payment_failed, expired, charge.refunded. No live or test credentials were installed in production.

Zoho inputs: product, organization ID, confirmed regional API/accounts host pair, access token, client ID/secret, refresh token, required scopes, VAT tax ID and document exposure policy. Configuration validation rejects unknown host pairs. Test mode requires a separately approved nonproduction organization; labeling an organization test is insufficient evidence by itself.

## Worker deployment contract

Scheduler POST `/api/public/hooks/accounting-worker` with `Authorization: Bearer <server secret>` over HTTPS. Secret is CORNERMEX_INTEGRATION_WORKER_SECRET, never a URL/query value. No public unauthenticated cron invocation. Suggested interval: one minute, one scheduler, bounded 25-job claim maximum (default 10). Scheduler timeout must cover the chosen batch; start with one job per invocation when provisioning and validate actual platform timeout before increasing it. Existing endpoint currently uses the default batch; configure platform timeouts accordingly. Requests remain safe under overlap because claims/customer leases use database locks.

Leases last 20 minutes; outbound calls have a 15-second deadline and require >20 seconds remaining. No lease renewal is performed. Crashed jobs are reclaimed with bounded attempts; exhausted jobs require attention. A stale worker cannot save mappings or finish another worker's claim. A provider may complete a request after a transport timeout; durable create intents prevent a later worker from issuing the same creation again when lookup cannot prove the outcome. Such jobs require operator reconciliation, not clearing the intent or retrying blindly.

Required server config: CORNERMEX_ZOHO_MODE, CORNERMEX_ZOHO_PRODUCT, CORNERMEX_ZOHO_API_BASE_URL, CORNERMEX_ZOHO_ACCOUNTS_URL, CORNERMEX_ZOHO_ORGANIZATION_ID, CORNERMEX_ZOHO_VAT_TAX_ID, CORNERMEX_ZOHO_ACCESS_TOKEN, CORNERMEX_ZOHO_CLIENT_ID, CORNERMEX_ZOHO_CLIENT_SECRET, CORNERMEX_ZOHO_REFRESH_TOKEN, CORNERMEX_ZOHO_LIVE_WRITES_ENABLED and worker secret. Stripe adds CORNERMEX_STRIPE_MODE and CORNERMEX_CARD_CHECKOUT_ENABLED to the existing checkout configuration. The database gate is required in addition to all environment values.

## Containment and controlled E2E

Before enabling providers: run read-only preflight, inspect historical queue counts, verify no enabled gate, and obtain separate migration/provider/scheduler approvals. No production fixture should be used. Rehearse against an isolated database and approved provider test organization, with a unique activation generation.

Controlled flow: duplicate card initiation → same order/attempt/session → verified success webhook → canonical paid/confirmed → one eligible invoice job → authenticated worker → one customer mapping and one invoice mapping → authorized invoice projection. Repeat signature rejection, mode mismatch, response loss, stale lease, revoked refresh, partial/full refund and multiple captures. Require actual captured evidence before marking production ACTIVE; environment flags are not telemetry.

Containment: disable checkout and worker execution flags and disable the provider gates through separately approved operations. Keep verified webhook ingestion available for existing payments. Preserve orders, payment/event ledgers, mappings, customer leases, create intents and refund actions for reconciliation. Do not down-migrate payment history, replay unknown backlog, delete create intents or auto-refund anomalies. In-flight external requests can have an ambiguous outcome and must be reconciled.

Invoice URLs fail closed unless the configured host is approved for exposing customer artifacts. Tokens/OAuth parameters are rejected. Unsupported/private URLs remain unavailable to customers; no unreviewed server proxy fetches arbitrary provider URLs.
